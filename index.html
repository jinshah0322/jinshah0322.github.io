A marketing analytics platform that has every client’s monthly report ready, with AI insights

Each client connects Google Analytics and Search Console once. From then on, the data arrives every night and the report is ready, with AI tips on what to improve.

Hard problem An AI insight is only useful if it matches the latest visits, clicks and search positions. Each insight is tied to a fingerprint of the data it describes, and a new one is written only when that data changes.

What it is

A platform for marketing agencies, live in production, where each client organisation has its own private space for its websites’ data and reports.

People can also ask questions about a client’s data in the AI assistant they already use, such as Claude or ChatGPT, through MCP, a standard way for AI assistants to reach a company’s data. For example, they can ask how a website did on Search Console this month.

The problem

An agency with tens or even hundreds of clients had to build a report for each one and hand it over at month end. Pulling visits, clicks and searches out of separate Google tools, client by client, made every month end slow and repetitive.

In more detail

  1. A client registers, joins their organisation and connects Google Analytics and Google Search Console once.
  2. Every night, visits and users, search clicks, impressions, search queries and positions are imported automatically.
  3. Dashboards show traffic, search results, Core Web Vitals (page speed and experience) and SEO health, by website and date range.
  4. AI writes short, plain-language insights on what is working and what to improve.
  5. The monthly report is ready to compare, export or share, and a team chat answers questions from it.

What changed

Month-end reports no longer have to be built by hand. Once a client is connected, the data, the report and the AI insights are ready in one place.

Stack

  • FastAPI

All features

  • Ask your own AI assistant (MCP): connect Claude, ChatGPT or a similar assistant and ask about websites, saved monthly snapshots, Google Analytics, Search Console, Core Web Vitals, SEO health or an executive summary. Each person gets a personal read-only key, and every request is logged.

  • Teams and sign-in: invite colleagues and choose who sees which website.

  • Traffic dashboards: visits, users and top pages from Google Analytics.

  • Search dashboards: clicks, impressions, search queries and positions from Google Search Console.

  • AI insights: a plain-language read of each section, with what to improve.

  • SEO check-up: Core Web Vitals, page health and visibility in AI search answers.

  • Monthly reports: scheduled, with downloads and share links.

  • Team AI chat: ask about any report, with sources shown.

  • Admin console: users, roles, plan limits and a logged support mode.

Every night, Google Analytics and Search Console data is imported for each client. The app server checks who can see which website, and AI works from the imported data and saved reports, so its insights match what the dashboards show. Outside AI assistants, such as Claude or ChatGPT, connect to the app server through MCP with a personal key, and follow the same access rules and time limits, with every request logged.

    The catch

    Many client organisations share one app, and each must see only its own websites.

    How it was handled

  2. 02

    The catch

    Fetching data from Google every time someone opens a page would be slow.

    How it was handled

    A scheduler imports the latest Analytics and Search Console data every night and stores it, so pages read from the database instead of waiting on Google. The Google access keys are stored encrypted.

  3. 03

    The catch

    AI text costs money each time it’s written, and an insight is only useful if it matches the latest visits, clicks and search positions.

    How it was handled

    Each insight is tied to a fingerprint of the data it describes. When that data changes, a new insight is written. Otherwise the saved one is reused.

  4. 04

    The catch

    Opening client data to outside AI assistants must not leak data or let one assistant overload the app.

    How it was handled

    Each person gets a personal access key, stored only as a one-way hash, so keys cannot be read back. Every call has a time limit and a cap on how much it returns, each one is written to an audit log, and admins can see usage.

A quality reporting platform with AI-built templates and a Word-like report editor

AI turns a company’s own Word template into a digital form, then drafts the report in a Word-like editor. People review and edit everything in place, sign off, and get the finished Word report.

Hard problem Auditors must be able to follow every result. Each check saves its calculation steps, so a result can be traced back.

What it is

A platform for pharmaceutical manufacturers, with each company set up as its own account. It is built around two features:

  • An AI template builder: AI reads the company’s own Word template section by section and builds the matching digital form and report template.
  • A Word-like report editor: inside the portal, AI drafts the report from the data, and people review and edit every section in place before getting the finished Word report.

Behind these, it imports data from Excel, PDFs and business systems (ERP), tests production records against quality limits and builds the annual quality reviews.

The problem

Every company has its own Word template, and rebuilding it as a digital form by hand is slow. Quality teams then had to gather data from several sources, check it by hand against each factory’s limits and type up huge reports for auditors. One retyping mistake could be expensive.

In more detail

  1. AI reads the company’s Word template section by section and builds the matching digital form and report template. If a section can’t be turned into a form, it is kept as plain text.
  2. Data comes in from Excel templates, PDFs and business systems (ERP). OCR (software that recognises printed characters) reads scanned pages, AI picks out the values, and a reviewer approves them.
  3. Quality checks test each record against the factory’s limits and save every calculation step.
  4. In the Word-like editor, AI drafts each section from the data and can rewrite a section on request. Drafts must fit a fixed format before they’re used.
  5. People review and edit everything in place, sign off, and get the finished Word report, with PDF and Excel copies too. Big reports build in the background, with progress on screen.

What changed

Templates no longer have to be rebuilt by hand, and reviewers start from an AI draft in a familiar Word-like editor instead of a blank page. Large reports build without holding anyone up.

  • Data imports: Excel, PDFs and business systems (ERP), with rows checked and corrected before saving.

  • Reading scanned records: simple matching is tried before AI, and reviewers’ corrections are reused.

  • AI usage limits: a logged allowance per company.

A business website for a clothing brand: story pages, a contact page and an online store that takes payments

The brand’s own website tells its story, gives customers a way to get in touch and sells its range online with secure payments. The team runs it all from its own admin panel.

Hard problem Each order must reach both the customer and the team without getting lost. The server saves each order once, and the customer’s account and the admin panel read that same record.

What it is

A complete website for a clothing brand: brand and about pages that tell its story, a contact page, a full online store with payments, and an admin panel the team uses to run it. The store and the admin panel share one server and database.

The same page types and contact form can be reused for other businesses, with or without an online store.

The problem

The brand wanted a website of its own that tells its story, is easy to buy from, safe to pay through and simple to run without a developer.

In more detail

  5. In the admin panel, the team manages products, categories and users, and handles orders.

What changed

The brand’s story, its store and its orders all sit on one website. Products are updated from the admin panel, and orders are tracked in one place.

An AI compliance assistant that answers from a company’s own documents and data

A chatbot for regulation questions, insights from uploaded PDFs delivered by email, and plain-English questions about the company’s own database, all with answers people can check.

Hard problem Letting AI write database queries against real data is risky. Each query is checked by the database before it runs, then runs through an account that can only read.

What it is

A subscription platform for pharmaceutical compliance teams. It brings four things together:

  • A compliance chatbot: answers regulation questions from the company’s own documents, with sources shown.
  • PDF insights: upload a document, such as an inspection report, and get a summary and insights by email, without having to ask.
  • Database questions in plain English: answered read-only.
  • A data assistant that learns from the company’s own material: its tables, documentation and example questions.

The problem

Answers were buried in long regulation documents, or in a database only technical staff could search. Inspection reports had to be read and answered by hand, and letting AI query real company data felt risky.

In more detail

  1. Chat: staff ask a regulation or compliance question in their own language. AI decides where to look (the company’s documents, a regulation reference or the database), and the answer appears word by word with the passages it came from.
  2. PDF insights: a user uploads a document, such as an inspection report, and gets a summary, key insights and suggested fixes without having to ask first. The report is also emailed as a PDF in the user’s language.
  3. Database questions: a question in plain English is turned into a database query by AI, checked by the database, and run through an account that can only read.
  4. Teaching it the company’s data: admins give the data assistant the company’s tables, documentation and example questions. What it has learned can be saved, backed up and restored, imported and exported, and a read-only console lets admins check its queries. This teaches the assistant; it doesn’t retrain the AI model itself.
  5. People sign in with a one-time code and subscribe to a paid plan with usage limits; payments are verified.

What changed

Compliance staff get quick answers with sources they can check, a head start on every uploaded report, and data answers without waiting for technical staff. Unanswered questions are logged, so missing material can be spotted and added.

Stack

  • Next.js
  • FastAPI
  • PostgreSQL
  • Azure OpenAI
  • Azure AI Search
  • Razorpay

All features

  • Compliance chatbot: answers regulation questions from the company’s own documents, streamed as they’re written, with sources shown.

  • PDF insights: upload a document, such as an inspection report, and get a summary, insights and suggested fixes by email, without having to ask.

  • Database questions in plain English: no query language needed, and each query is checked and run read-only.

  • Teaching it the company’s data: tables, documentation and example questions, saved, backed up, restored, imported or exported, with a read-only console to check queries.

  • Question routing: questions translated if needed, then sent to the likeliest source.

  • Knowledge-base admin: manage, back up and restore the documents the chatbot answers from.

  • Accounts, plans and billing: one-time-code sign-in and verified subscription payments.

  • Data publishing: new data is published only after an admin approves it.

One chat server translates each question, asks AI where to look, and streams the answer back with its sources. Uploaded PDFs go to a background worker for a summary and insights. The data-question assistant works from a training store of the company’s tables, documentation and example questions, and its queries run read-only.

Payroll automation that reads employee PDFs, so nobody retypes them

AI reads the documents, and a person approves every result before it reaches payroll.

Hard problem AI can misread a document, and one wrong detail could mean a wrong salary. AI only proposes a record, and only approved records are saved for payroll.

What it is

A web app that turns employee PDFs, sent by staff on site and at client locations, into clean payroll records.

The problem

Before each salary run, someone opened every PDF and retyped the details. It was slow, and one typo could mean a wrong salary.

In more detail

  1. Staff upload PDFs from each site in one place.
  2. Background workers read the text and tables in each PDF.
  3. AI turns that text into employee records.
  4. A reviewer checks each record, and approved records are ready for salary processing.
  5. Failed jobs are set aside and can be retried from the app.

What changed

There’s less retyping before each salary run: staff review details pulled from the PDFs instead of typing them.

  • Review screen: a person checks and approves each result.

  • Results screen: approved data, ready for payroll.

  • Failed-job recovery: failed jobs are kept and can be retried from the app.
